## 2026-07-09 — Session S98: durability capstone + begin vision funnel (P1–P4, all shipped, pushed, deployed live)

- P0 #pattern-heartbeat-presence-is-the-crashloop-signal: The 5.5-week dark outage was invisible because the only crash signal was a >60s heartbeat-staleness check, and a fast restart always rewrites a fresh heartbeat before it fires. The real signal hid in plain sight: the heartbeat file is unlinked ONLY on graceful shutdown, so its PRESENCE at boot already means the prior run ended uncleanly, and its recorded `uptime` says how long that run survived. Short (<5min) unclean run ×3 = crash-loop → degraded. Detection must run BEFORE startHeartbeatFile() overwrites it. A counter meant to detect torn-write crashes must itself tolerate a torn counter file (readJsonSafe→0), write atomically, and be named so cleanupStaleTmps (reaps *.tmp-*) can't wipe it. Validated live: after killing a ~21h-uptime server, the counter correctly reset to 0 (healthy prior run, not a loop).

- P0 #pattern-verify-the-persistence-HOOK-not-just-the-save: The adversarial pass caught a HIGH defect the synthesis rubber-stamped — the event-driven save for paid conversions was scoped to the /checkout POST, but the entitlement is only granted later in the Stripe WEBHOOK (ticket-routes.ts grantTicket, checkout.session.completed). A save at /checkout persists NOTHING; it would have been a fix that provably doesn't survive the crash it claims to prevent. For "save after high-value mutation", trace WHERE the mutation actually lands (and confirm attachSidecarData serializes it — _ticketState at :1203) before choosing the hook site.

- P1 #pattern-name-the-proxy-before-picking-the-header: The rate-limit-collapse fix hinged on which header the proxy forwards. `trust proxy: true` is spoofable (security regression); `trust proxy: <hop>` silently fails if the proxy only sets CF-Connecting-IP not XFF. Resolved by EMPIRICAL state-discovery (read .cloudflared/config.yml → Cloudflare Tunnel to 127.0.0.1) not guessing: trust ONLY loopback + key the sensitive limiter on the edge-authoritative CF-Connecting-IP. Proved with a real-HTTP test whose key assertion (a different XFF must be a FRESH bucket) fails loudly if req.ip ever collapses to loopback again.

- P2 #pattern-apply-at-the-effective-reward-not-the-stored-quest: The reveal flags were dead because the EmergentQuest instance never stores flags/title/chronicle (only rewardDeniers/rewardReputation survive instantiation) AND the standard path strips the reward in the caller. So the fix could NOT live in resolveEmergentQuest (no data there). The right seam was completeEmergentQuest, which already looks up the template — apply the missing reward TYPES from the EFFECTIVE reward (choice.rewards vs template.rewards), split by data-ownership (flags→playerState, title/chronicle→gameState via applyReward), leave deniers/reputation untouched (no economy shift), and guard title/chronicle to standard-path-only to avoid double-applying the choice path.

- P2 #pattern-immutable-helper-return-must-be-assigned: chronicle.addEntry() returns a NEW ChronicleState and does not mutate. Two call sites (reward + consequence) discarded the return, so EVERY quest-driven chronicle entry was silently lost — invisible because nobody asserted on chronicle. Only a test asserting the entry APPEARS surfaced it. Rule: when a helper returns state (immutable style), grep every caller for `x = helper(x)` vs a bare `helper(x)` — a bare call is almost always a dropped write.

- P3 #pattern-gate-and-allowlist-distributable-artifacts: A shareable/downloadable artifact is a one-way information release — treat inputs adversarially. Two gates made the Royal Summons safe to ship before the T3.1 anachronism filter exists: (1) a persona ALLOWLIST (known class, clamped rank, period-safe title charset) so no player-influenced/emergent field stamps a modern token on a hard-1601 image; (2) a DATE GATE (REAL_FESTIVAL_DATE=null → "proclaimed anon") so an unconfirmed year never propagates on an image people screenshot. Both were adversarial-challenge findings, not obvious from the happy path. Keeping the render 100% client-side (canvas→PNG, reusing the shipped og-card pattern) delivered the funnel piece with zero new deps and zero infra.
