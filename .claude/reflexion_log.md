# Reflexion Log — Legacy of the Realm

Cross-session learnings for the PDCA pipeline. Newest session at top. Pruned to ~50 entries; older entries live in archived handoff docs.

## 2026-08-29 — Session S121: the server switched on, the world began keeping time, and night arrived

- P0 #six-research-tracks-reasoned-about-a-server-that-was-switched-off: Fifteen research reports, a 3-way Council, and my own PDR all assumed the save path was live. One curl showed 503 not-configured: zero accounts, zero rows, ever. It reordered the whole session and made the schema free to change. Probe production BEFORE reasoning about it, not after.

- P0 #the-blocker-i-carried-for-a-session-did-not-exist: The $5/mo Workers-Paid decision was described as load-bearing in the handoff, the boot snapshot and my own PDR: PBKDF2 ~29 ms against a 10 ms Free CPU limit means login FAILS. It registers in ~310 ms on the apex, four times in a row. A measurement carried forward as a fact is still only a measurement, and the cheapest way to retire it was to try it.

- P0 #applied-is-not-the-same-as-matches: apply-schema said "schema: OK" while the realm foreign key had silently not applied - CREATE TABLE IF NOT EXISTS is a no-op on an existing table, and the verifier only asked whether tables and indexes EXIST. Anything a schema file can add to a FRESH database but not an EXISTING one has to be asserted explicitly, or the gap is invisible exactly when it matters.

- P1 #the-plan-was-pre-taken-and-one-parameter-of-it-was-measurably-wrong: The handoff said DO NOT RE-PLAN these and it was right to. But A.0 is not re-planning: STEP_MS=190 means 5.26 local saves/second, so the pre-taken "5 s trailing debounce" could never fire while anyone was walking, and the pre-taken negative test ("a handful, not hundreds") would have passed with ZERO. Follow a pre-taken plan; still measure its numbers.

- P1 #the-test-found-the-bug-that-reading-had-walked-past-twice: I read push() closely enough to quote its header about stale, and still missed that it never calls isOutage() — so a 503 read as "the server refused your save". Harmless while nothing pushed; fatal with autosync, which treats rejected as final. The test caught it in seconds. Reading proves what code says; running proves what it does.

- P1 #i-rejected-a-bug-the-reviewer-invented: The applicability critic reported dropped[key]=item as an unguarded data-loss/grief primitive. Both write sites are guarded by an itemAt() check and the file even has a comment about the hazard. PRIME-AUDIT applies to the reviewer too — a confident critic is still a claim to verify.

- P1 #the-owner-reframed-and-it-changed-the-answer-not-just-the-scope: "Multiple servers, the world keeps living" turned autosync-the-blob from the fix into the wrong move: it would have made every player the author of a world meant to be shared. The code had called it years earlier — "this is the half a server takes over". Read what the codebase already knows before designing against it.

- P1 #a-credential-went-into-chat-because-i-asked-for-it-in-the-same-breath-as-the-file: I said "paste into the vault, not into chat" and he pasted into chat. Naming the file path and the exact line FIRST, before mentioning the value at all, would have made the file the obvious target. Rotated; the exposure is the instruction design, not the person.

- P4 #the-name-said-world-and-the-contents-said-player: worldFlags holds only era and intro.seen — both per-player progress. A future session moving it server-side because the NAME says world would give every player one shared intro.seen and one shared era. The most dangerous kind of misnaming is the kind that reads as a specification.

- P4 #a-grep-for-literal-calls-missed-the-dynamic-one: I reported worldFlags held exactly two keys, from grepping setFlag('name'). ParcelScene writes setFlag(act.openFlag) with a name from map data, so it also held a real world flag. The claim was confidently stated to the owner and was wrong. Grep finds the calls you can spell; it does not find the ones the data spells.

- P4 #the-failing-test-might-mean-the-data-is-gone: Six migration assertions failed with "keeps the era". The comfortable reading is "the test checks the old location". The other reading is "the era was lost". I migrated a real v8 blob in isolation and inspected it BEFORE editing a single expectation. Never update an assertion until you have proved which of the two it is.

- P5 #the-optimiser-satisfied-the-metric-and-produced-green-skin: An automatic pass to separate colliding night palettes turned a BLACK car bright orange and gave an NPC green skin with purple steel. Numerically valid, visually absurd. And the metric itself was wrong twice: comparing ONE step of a ramp fires on coincidence, and an absolute threshold punished materials that are near-identical in DAYLIGHT. A palette that satisfies a metric and looks ridiculous has not been fixed - the metric has been gamed.

- P5 #the-principled-fix-was-smaller-than-the-numeric-one: Dael and the crowd kept colliding with stone and gravel at night. The numeric answer was to shove their hues apart, which produced the green skin. The right answer was one line: they are PEOPLE, and people do not dim - the same rule that already exempted the player, and the one GSC shipped by leaving sprite palettes alone. When a constraint keeps fighting you, check whether the thing belongs in the constraint at all.

- P6 #it-looked-like-it-worked-and-half-the-palette-was-untouched: The LUT builder quantised with v>>2 and the shader with floor(v/255*63+0.5). 192>>2 is 48; the shader says 47. Forty-eight of 103 colours read an empty texel and passed through UNCHANGED - while the frame still lost a measured 23% of its luminance, so every summary number looked healthy. Found only by reading real pixels and noticing ONE colour was byte-identical at factor 0, 0.5 and 1 while its ramp neighbours moved. When two pieces of code must agree on a number, one of them has to be the definition; here it is the shader, because the shader is what does the lookup.

- P6 #i-measured-a-fade-and-nearly-reported-it-as-the-feature: My first pixel reading said night made the world BRIGHTER. The camera fade-in was still running at 42%, and my two grabs were two frames apart on a rising ramp - so I measured the fade, not the palette. Settling it first reversed the conclusion completely. A measurement taken during a transient is not a measurement of the thing.

- P6 #i-read-a-truthy-global-as-proof-and-it-was-a-pane-artifact: window.game existed, so I said the whole boot path ran. It was an empty object with no .scene and no .canvas in a 0x0 viewport, while the auth gate was still on screen - which would have meant the opposite. Giving the pane a real viewport settled it. Eight sessions of this repo learned not to read unmeasured frames; a truthy global is the same mistake wearing a different hat.

- P6 #the-author-said-the-player-holds-no-decisions-and-it-held-three: The audio module claimed its player function was dumb enough not to need testing, and it nearly was. Three decisions lived in the walk and in none of the data: skip-or-queue on a suspended context, claim-or-not on a turn that never sounded, and whether the gain ceiling survived. Each breakable without moving one number in the arrays. An adversarial pass found them and covered them with a witness that records and interprets nothing.

## 2026-08-27 — Session S120: eleven priorities, the game deployed and seen, and a research pass before multiplayer

- P1 #the-instrument-existed-and-nobody-ran-it: S119 shipped accounts and characters and saw none of it, and the reason was written down wrong: rule 7 said WebGL could not be screenshotted here. 89 frames from S116-S118 were sitting in docs/shots the whole time. The lesson is not LOOK AT IT, which was already a rule. It is that a FALSE EXPLANATION for why you cannot look costs more than no explanation, because it retires the question. I nearly inherited it: my first instinct was to propose adding preserveDrawingBuffer. The probe took thirty seconds.

- P1 #the-footer-was-the-spec-and-both-keys-broke-it: The name page footer says ENTER / F TO CONTINUE. Neither key does that: ENTER turns two pages and F types itself into your name. Nothing in 3155 assertions, nine guards or tsc could see it, because every one of them tests what the code does and none tests what the screen PROMISES. The footer is a spec written in 11px text and it was never checked against behaviour.

- P1 #i-was-wrong-twice-and-measurement-caught-both: I read a collision off a frame that had a 7.5px gap, and I claimed the animation leaked onto every journal page when two of them return early. Both were corrected within a minute by getBounds() and by reading the return structure. The eight-for-eight record here is not carelessness; it is how confident a rendered frame makes you feel. Measure, then look, then say.

- P1 #a-guard-that-passes-after-the-bug-happens: check:surfaces PASSES on the Journal and prints that redraw() clears both surfaces. It does. The diagram is drawn AFTER the redraw, inside update(), which the guard does not model. A guard scoped to one function proves that function, and the page S119 added was wired into a different one.

- P2 #the-comment-was-the-risk-not-the-code: I opened the PDR with a risk: handDown is also the aim machine's release detector, so those eight lines are not isolated. I got that from the function's own comment. One grep showed handDown is called from a single site and the aim machine has used its own key since S115. The comment had outlived the code by five sessions and I had quoted it to him as a hazard. Read the callers, not the prose about the callers.

- P2 #my-own-green-verdict-was-confounded: The walk-suppression test printed CONFIRMED and the data underneath it was junk: every position was the (-1,-1) sentinel, so nothing had moved for reasons that had nothing to do with the hand key. I had written the verdict string myself and it lied to me. Re-ran it with a control -- prove the walk works from this tile FIRST, then repeat it holding the key. A test with no control is a sentence with no verb.

- P2 #the-browser-serves-the-bundle-not-the-source: After editing ParcelScene.ts I nearly tested the page as it stood. The browser loads dist/main.js, dated before the edit -- so every assertion would have described the OLD behaviour and passed for the wrong reason. Rebuilt first, then verified the minified artifact structurally, because esbuild strips the comments I would otherwise have grepped for.

- P2 #i-invented-a-vocabulary-and-called-it-verification: I wrote 16 assertions in types that do not exist: file_min_bytes, runtime_behaviour, bundle_structure, gate, and file_not_contains, which is just the wrong name for file_lacks. Every claim underneath them was true and I had checked each one live, and that is exactly what made it comfortable: the verification array LOOKED rigorous and was unexecutable. The MCV hook caught it, not me, and only at Stop. Read the vocabulary of the checker before writing assertions for it. Note the shape of the error too: I did not fake evidence, I made evidence that nothing could read, which fails the same way at the moment it matters.

- P3 #green-is-not-deployed: For two sessions the game was built, committed, pushed, and a green Deploy site tick appeared on every push. Nothing was deployed. The job checks for CLOUDFLARE_API_TOKEN, finds none, sets ready=false, skips Install/Bundle/Assemble/Deploy, and exits SUCCESS -- 12 to 17 seconds, green. The workflow author wrote that a missing token must SKIP LOUDLY rather than fail red for months; loudly was implemented as ::notice::, the quietest annotation GitHub has. The owner asked why he could not see his own character creation and the answer was a green tick that meant nothing. A skip that reports success is worse than a failure, because a failure gets fixed. Never treat a green deploy as evidence of a deploy: fetch the artifact back and compare bytes.

- P4 #i-reported-an-absence-i-had-not-actually-searched-for: I told him the apex deploy was blocked on him because there was no Cloudflare token in the vault. There was. My probe matched key NAMES against cloud|cf_|wrangler|account_id -- it found cloudflare.account_id, printed four hits, and I read that output as a complete answer about a key called api_token that my own regex could never have matched. A negative result is only as wide as the query that produced it, and I presented a query artifact as a fact about the world while he sat blocked on an action he did not need to take.

- P4 #the-error-message-said-safe-while-it-locked-the-door: The lockout shipped with a reassuring sentence: Saving is not switched on yet. Your game is safe on this device. Every word true, and the device could not reach the game at all. The bug was one line -- status != 201 means rejected -- and it turned a degraded feature into a total outage for every new player. When a fallback path exists in the design (AuthGate has an offline branch and a comment saying the game is playable with no server), test that the CLASSIFIER can actually reach it. An unreachable fallback reads exactly like a working one in code review.

- P4 #my-verdict-string-said-still-blocked-about-a-working-deploy: Second time this session. I keyed the pass/fail on window.__realm, which main.ts sets ONLY on localhost -- by design, and documented in the boot snapshot I read at boot. So the successful production deploy reported STILL BLOCKED and I nearly relayed that. The signal I chose could not be true in the environment I was testing. Choose the observable from the environment under test, not from the one where the harness was written.

- P5 #it-was-drawn-as-a-button-and-was-not-one: Four bordered boxes across the top of the journal, the live one filled. That drawing is a promise: these are selectable. Nothing in the input model agreed -- no focus state existed, and UP wrapped to the bottom of the list. The S119 note in this very file says the strip replaced a current-plus-next pair because ACCOUNT was invisible from KEYS unless you already knew to keep pressing; the fix made the pages VISIBLE and left them unreachable by the gesture the new drawing invited. Solving discoverability by drawing something is only half a fix if the thing drawn does not respond.

- P5 #a-label-computed-for-four-pages-and-printed-on-one: `turn` -- the page-turn key, read from the live keymap -- was computed on every redraw of every page and appeared in exactly one branch of the footer ternary. Nothing failed. tsc was happy, the value was used, no lint would flag it. The only symptom was a player who could not find a page. A value computed for a general case and consumed in a special one is a defect with no error message, and grep for the variable name found it in seconds once I stopped reading the code that ran and started reading the code that printed.

- P5 #i-wrote-a-test-that-could-not-fail: Third time this session, and the most instructive. To prove the tab strip does not also flip a help card, I pressed RIGHT then LEFT and asserted the card index was unchanged. It was -- and it would have been unchanged whether the bug existed or not, because 0 -> 1 -> 0 is 0. I caught it only because the symmetry looked too comfortable. A test whose pass condition survives the bug is worse than no test: it converts an open question into a false answer. Make the probe ASYMMETRIC and always include a control that proves the mechanism can move at all.

- P6 #the-cure-was-already-in-the-repo-with-a-comment-about-this-bug: Before writing a way to swallow the pending key edge I grepped for one, and found InputMap.drainEdges() - already implemented, already used by the Journal's rebind capture, and carrying a doc comment that explains the precise race I was about to re-derive: Phaser registers its window listener at boot, so a capture handler added later cannot win, whatever it does with stopImmediatePropagation. S114 paid for that knowledge and wrote it down. Creation was built afterwards with the same pattern and never called it. The lesson is not 'read the code' -- it is that a repo which writes its scars down is only protected if you search the scars before inventing a cure.

- P6 #my-test-data-was-invalid-and-it-looked-like-a-regression: After the ENTER fix the page would not advance at all, and the honest first reading was that I had over-corrected and broken forward navigation. Instrumenting canAdvance() instead of reasoning about it showed the truth in one call: the name `testp6` contains a digit, a character name forbids digits, and the refusal was correct. Two things fall out. Instrument before concluding, because 'my fix broke it' and 'my input was invalid' look identical from the outside. And the accident found a real bug -- the page pre-fills from the account username, which permits digits the character name rejects -- so anyone called daniel99 hits a silent refusal on their first play. A bad test can be better evidence than a good one if you find out WHY it failed.

- P6 #i-probed-the-two-i-could-not-do-before-saying-i-could-not: He said do all four. Two were his to unblock, and earlier this session I had already told him something was blocked on him that was not (the Cloudflare token was in the vault all along). So this time I probed both before reporting: the zone reads fine with the workers token but rulesets returns 10000, and the dns token returns 7003 on rulesets and pagerules; the vault has no Neon API key under any name I could match. 'I cannot' is a claim about the world and it needs the same evidence as 'I did'.

- P7 #the-fix-that-made-it-pure-also-made-it-a-trap: Routing the name page through the keymap and deleting the literal `e.key === 'Enter'` was the clean version, and it introduced a soft-lock: a printable key must type on a page that takes a name, so a player who binds engage to a letter and clears its secondary would have had no way forward at all. Input.ts promises a primary EXISTS; it never promised the primary is non-printable, and I had read the first guarantee as if it were the second. Caught it by asking what the change REMOVED rather than what it added. The shipped version is additive -- ENTER used to be the only key that could act and is now the key that can always act.

- P7 #sanitise-the-offer-not-the-rule: Two validators disagreed -- an account name may hold digits, a character name may not -- and the page pre-filled one into the other. There were two directions: loosen the character-name rule, or stop proposing values it rejects. The rule is a deliberate 1601 constraint, so loosening it to make a prefill work would have let the convenience rewrite the design. Fixing the OFFER kept the rule intact and removed the trap. When two rules disagree, check which one is load-bearing before reconciling them.

- P7 #a-game-set-in-france-needs-its-accents-tested: I wrote a character filter and immediately tested Helene, Aime, Gaelle, Francois and Maitre d'Armes, because a sanitiser is exactly the code that silently eats an accent and nobody notices until a French player types their own name. All survived. My first probe DID report a false negative and the cause was my test string -- 'e' plus a combining accent is two code units and the length===1 gate rejects it, while the precomposed character a real keyboard sends is one. Test the input the machine actually produces, not the one you can type in a script.

- P8 #the-stale-row-was-the-before-picture: My first database query after stripping the credential showed the hash still sitting in the save blob, and the honest first reading was that the fix had not worked. It had; I had run typecheck and the suites but never rebuilt the bundle, so the browser was still executing pre-fix code -- the exact trap I wrote a reflexion about earlier the same day. The difference is that this time it surfaced at verification instead of in a claim. And the stale row turned out to be the most valuable artifact of the priority: it is the BEFORE half of a before-and-after on real stored data, which no amount of reading the diff could have produced.

- P8 #the-feature-was-half-wired-and-the-comment-admitted-it: While verifying the credential fix I looked for what calls push() and found two sites, both in Restart.ts. Nothing uploads the world during play. main.ts says it in plain words -- 'nothing upstream -> keep this device's world, push it later' -- and later never comes. The owner has been waiting on a Neon connection string believing it was the last mile of cross-device saves; it is one of two halves. I found this only because I needed a push to fire in order to inspect a payload. Verifying a fix walks the path the feature walks, which is why it finds things reading cannot.

- P9 #a-skip-that-reports-success: The deploy job checked for a token, found none, skipped every step and exited SUCCESS -- by design, with a comment explaining that a permanently-red job trains people to ignore the tick. The reasoning is genuinely good and the outcome was two sessions of invisible work and an owner asking why he could not see his own game. The flaw was in the implementation of 'loudly': ::notice:: is the quietest thing GitHub has. A skip that reports success is worse than a failure, because a failure gets fixed. When reversing a documented decision, argue with the record rather than deleting it.

- P10 #chosen-for-slack-not-for-fitting: Ten candidate strings measured with the real font; four fitted. I took the one with 24px of slack over one that ended exactly on the margin, because this repo already knows the answer -- Journal's wrap() records that glyph advance is whatever the machine resolves it to, 6.03px here and not necessarily on a phone. The bug I was fixing WAS an overflow. Fixing an overflow with a zero-margin fit is agreeing with the bug about how much room there is.

- P11 #i-told-him-a-platform-limit-from-memory-and-it-was-wrong: Asked whether players could share a server, I said Cloudflare realtime needs the paid plan 'as far as I know' and added that I would verify rather than quote a price I half-remembered. - CLOSE #the-cleanup-step-found-the-bug-the-work-never-would: Releasing the session port at handoff surfaced four orphaned Postgres containers, the oldest 25 hours old and therefore from the PREVIOUS session. - CLOSE #i-asserted-against-a-file-a-generator-owns: The last MCV red of the session: an assertion pinned a phrase in boot-snapshot.md, and STEP 2.95 of /handoff rewrites that file from scratch every time.
