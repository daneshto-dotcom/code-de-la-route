## 2026-08-29 — Session S122: the gates were not gates, and the multiplayer that was never tried worked

- S122-P1 #the-gate-had-been-reading-a-third-of-the-repo: `npm run typecheck` was printed as a gate in every handoff for twenty sessions while tsconfig included only src/**/*. Every test suite, realm-build, and all nine build guards sat outside it. The filed finding said 'tests'; the hole was the whole directory. A gate is only as wide as its include list, and nothing anywhere stated that width.

- S122-P1 #silence-read-as-approval: Nothing could distinguish 'tsc passed' from 'tsc had nothing to say about this file' -- both print nothing. That is why the fix needed a GUARD and not just a one-line include: the one line of include is exactly what regressed. check:typecheck-coverage asks tsc what it actually LOADED and set-differences it against disk.

- S122-P1 #six-hand-written-shadows-of-types-that-already-existed: 46 of 79 errors were five structural copies of the real Store/SaveData, cast in with `as unknown as`, drifted four members behind. S121's own lesson -- when two places compute one number, one must be the definition -- in the type system rather than a shader. `typeof import(...)` erases completely, so the fix cost one line each.

- S122-P1 #i-broke-ci-and-my-own-new-guard-caught-me: @types/node was never declared in rebuild/; it resolved by Node walking UP into the OLD build's node_modules. CI installs only rebuild/, so it vanished. src/ is browser code with no node: imports, so typechecking tools/ is what exposed it. My local gate was fully green -- typecheck 0, 10/10 guards, 3,966 assertions -- and could not see it. ci:status, shipped an hour earlier, caught it in four minutes.

- S122-P2 #a-skip-that-reports-success-is-worse-than-a-failure: The owner asked why it says it works. Committed and pushed were TRUE; works was never checked by anything. The 17 green ticks were the lie and the 9 red ones were S120 P9 telling the truth for the first time. Every command in the gate was local; not one could see GitHub. Rule 22 already said to check gh run list -- prose lost to six commands that print PASS.

- S122-P2 #my-own-control-refuted-the-comment-i-was-shipping: I wrote into the workflow that `[ -z $X ] && missing=...` would kill the step under bash -e. My own control test, run in the same breath, showed it does not: a failing && list is exempt from set -e mid-script and only fatal as the final line. I had a plausible mechanism and shipped it as fact for one minute. The comment now states the measured, narrower thing.

- S122-P2 #a-guard-that-can-never-pass-becomes-a-guard-nobody-reads: ci:status's first run found three red, not one. Two were parked dispatch-only workflows whose last run is red forever because nothing will overwrite it. Failing on those every time would have made the new guard permanently red -- reproducing the exact bug (train everyone to ignore the tick) that deploy-site.yml was written to avoid. Separated RED-NOW from PARKED-RED.

- S122-P3 #a-red-notification-is-not-a-red-repo: Two of the four repos in the owner's screenshot had already fixed themselves days earlier. Diagnosing from the notification list rather than from live state would have produced two confident wrong findings. Ask the system, not the screenshot of the system.

- S122-P3 #the-worse-failure-was-the-one-not-in-the-screenshot: navlog-pro's weekly refresh has failed five times on an external GeoJSON returning 400. Ours failed loudly and did nothing; that one means airspace data has been stale for five weeks -- a WRONG answer rather than an absent one. Severity did not track how loudly a thing complained.

- S122-P0 #the-staleness-guard-was-already-red-before-i-arrived: The handoff's gate line said '9 guards'. Run at HEAD it was 8 -- world-index recorded its inputs' mtimes from 26 Aug while S121's own prebuild rewrote those files on 29 Aug and never re-ran worldindex. I checked whether I had caused it (git status: none of the inputs touched) before fixing it. Third instance in one session of a gate reported as passing that was not.

- S122-P0 #binding-an-assertion-to-prose-punishes-honest-corrections: MCV hard-failed at close on S118-P3's pinned sentence 'THIS WORKFLOW HAS NEVER RUN', which S122 P2 deliberately rewrote because it had become false (26 runs; the deploy STEP never executed). Third sighting of CF-S114-MCV-VERSION-ASSERTION-CLASS, now on prose rather than a version number. A file whose purpose is to state what is unproven WILL be reworded as the truth changes. Bind to the claim.

- S122-P4 #the-owner-doubted-a-feature-and-was-right-about-the-only-thing-that-mattered: I said the clock existed on the Journal's ACCOUNT page. True, and useless: on his machine it rendered THE HOUR IS UNKNOWN FROM HERE. A feature nobody walks past, showing its failure text, is indistinguishable from one that was never built. 'Where is it' and 'can he see it' are different questions and I answered the wrong one.

- S122-P4 #a-grep-returning-zero-because-the-import-was-dynamic-twice-in-one-session: I diagnosed 'dev-api.mjs never sends serverNow' from a 0-hit grep. It imports the real Handlers.ts DYNAMICALLY, so a static grep cannot see it — the second time this session a dynamic import defeated a literal search. The real cause was that I had started `npm run dev`, which has no /api at all, and then blamed the code for my choice of server.

- S122-P4 #the-assertion-i-expected-to-be-bookkeeping-caught-the-defect: I asserted the clock line was one width at every hour purely to have something to assert. It was three — DAY/DUSK/NIGHT differ — and with setOrigin(0.5) both edges would slide every time the sky turned, the exact jitter formatRealmTime zero-pads the hour to avoid. The throwaway assertion found the bug the careful ones missed.

- S122-P5 #the-research-recommended-a-number-that-would-have-fought-the-player: RESEARCH-multiplayer.md called the old engine's MOVE:500 'a shipped, tuned figure for exactly the action we care about'. STEP_MS is 190, so real walking is 5.26 tiles/s and 500ms would have rejected more than half of it. The figure was tuned for an action pipeline of labour and guild charters. A number is only tuned for the thing it was measured against, and 'shipped' is not the same as 'applicable'.

- S122-P5 #the-right-types-broke-four-guards-so-the-shadow-was-correct-this-time: Having just deleted six hand-written type shadows in P1, I reached for @cloudflare/workers-types instead of writing one. It typechecks Presence.ts perfectly and replaces the global Buffer: 0 errors became 16 across bundle-check, comic-check, palette-check and explorer. TS has one global scope per program. The rule 'never hand-write a type that exists' is about types you OWN; for a platform type whose package is hostile to the rest of the program, the narrow shim is right — and the measurement belongs in its header.

- S122-P5 #esbuild-would-have-bundled-a-file-no-test-could-import: constructor(private state: X) is erased by esbuild and REJECTED by node --experimental-strip-types, which every tool here runs under. The bundle would have been fine and the test suite could never have touched the file. A thing that builds is not a thing that is testable, and in this repo the tools are the test runner.

- S122-P5 #the-sentence-promising-no-route-key-tripped-the-check-for-it: I appended a comment saying 'No routes key was added'. The S119 assertion is a plain substring check, so the promise failed the check for the thing promised — twice, because my first rewrite mentioned the regex containing the word. I kept the over-broad assertion anyway: earlier this session the right answer to a broken pinned sentence was to loosen it, but that one cost nothing if stale and this one can take the live domain down. Blast radius, not consistency, decides how tight an assertion should be.

- S122-P5 #a-baseline-taken-before-the-first-edit-is-what-makes-nothing-broke-a-fact: The owner's whole instruction was 'dont break anything'. Recording typecheck/suites/assertions/guards/bundle-hash BEFORE writing a line turned that from a reassurance into a measurement — and the byte-identical dist/main.js was the single most convincing line in the report, because it proves the shipped artifact did not move rather than arguing that it should not have.

- S122-P7 #i-measured-the-layout-and-the-measurement-picked-the-design: Adding a fifth Journal tab looked like a one-line change. Computing the strip first showed SERVER would land at x=36 with the title ending at x=52 - straight over it - and that a sixth tab runs clean off the page. The label 'HOW TO PLAY' became 'PLAY' because 42px was exactly what was missing. Had I written the tab first I would have shipped a collision and called it done.

- S122-P7 #the-honest-label-was-the-harder-one-to-write: He asked for a tab showing 'players that are currently logged onto the server'. Presence is per-parcel, so a client in the cellar cannot see the courtyard - the tab says WHO IS IN THIS PARCEL. Labelling a per-parcel list 'ON THE SERVER' would have matched his words and been the same class of claim as a green tick that deployed nothing. The gap is real and is written down rather than papered over.

- S122-P7 #a-sheet-with-stale-gear-is-worse-than-a-sheet-with-none: The cheap way to ship 'equipped items' was to carry them on hello. It works, and it is wrong within a minute of the first hand swap. Gear became its own message - not on hello (goes stale), not on step (five a second while walking) - and was proved live: B saw {bottle_empty, key_iron} then the update to {null, lantern}.

- S122-P7 #the-dev-watcher-had-been-corrupting-the-shipping-artifact-all-session: A 5x size discrepancy against the live site turned out to be `npm run dev` running esbuild in WATCH mode, rebuilding dist/main.js UNMINIFIED on every edit - 7.1 MB against the 1.47 MB that ships. `npm run check` passed 10/10 with it in place, because check:bundle tests neither size nor minification. VERIFY THE ARTIFACT NOT THE SOURCE is this project's own rule, and the artifact was quietly wrong while I was measuring it.

- S122-P7 #both-deploy-failures-were-whitespace-and-the-changing-error-was-the-signal: The first deploy failed 7003 'object identifier is invalid' and the second 6111 'Invalid format for Authorization header'. Neither was a wrong value - the vault token has the right scope and no whitespace - both were characters picked up by an interactive paste prompt. The useful move was noticing the error CHANGED after the first fix: that is what proved the account id was now right and turned a vague 'auth is broken' into a second, narrower question.

- S122-P7 #bind-the-claim-not-the-spelling-for-the-third-time-today: Two more assertions failed on legitimate growth - S117-P7 pinned the exact Page union, S119-P3 the exact PAGES array, and P7 added a fifth page. Rebound to prefixes so the original four and their order are still proved. Third instance in one session after a pinned sentence and a 'routes' substring. And the counter-example matters: S119-P4 stayed over-broad deliberately, because a stray route key can take the live domain down. Blast radius decides tightness, not consistency.

- S122-P8 #the-patrol-that-executed-the-function-found-what-reading-it-missed: I reviewed the move handler, wrote it, tested around it, and shipped a line that emptied every peer's hands on their first step. A patrol RAN the two functions and reported {right: key_iron} before and {right: null} after. Reading code proves what you expect it to do; running it proves what it does. The gear message existed specifically to prevent a stale sheet, and the bug made every sheet permanently wrong.

- S122-P8 #the-bug-and-the-test-gap-were-the-same-shape: The gear wipe survived a 17-section test file because the expression was INLINE and nothing drove a move after a join. Untestable code and untested code are the same problem wearing different clothes. The real fix was not the missing field - it was extracting applyMove() so the thing that was wrong became a thing a test can hold.

- S122-P8 #the-gate-every-handoff-cites-never-typechecked-anything: npm run check is realm:build plus ten guards, and build is esbuild + check - esbuild strips types without checking them. A planted type error gave tsc 1 error and check exit 0. Twenty sessions of handoffs listed that chain as the gate. This is the SECOND time in one session that a gate turned out not to cover what everyone assumed: the first was typecheck never reading tools/ at all.

- S122-P8 #a-citation-can-be-invented-and-it-reads-as-the-strongest-sentence: Input.ts cited tools/input-equivalence.test.ts as proving the default keymap against the former literals. Zero commits on any branch; the file has never existed. The reasoning was sound and the evidence fabricated, and a neighbouring citation in the same docblock IS real, which made the false one harder to see. The MCV gate catches this in claims; nothing catches it in prose.

- S122-P8 #the-correction-loses-when-it-is-appended-instead-of-applied: Four documents carried both the correction and the uncorrected original, with the stale copy in the header a session reads first. One of them was a paragraph I wrote THIS MORNING - true when written, false ninety minutes later, and made more convincing by a MEASURED tag and a citation. The path nobody tests is the one every real user takes first.
## 2026-08-29 — Session S121: the server switched on, the world began keeping time, and night arrived

- P0 #six-research-tracks-reasoned-about-a-server-that-was-switched-off: Fifteen research reports, a 3-way Council, and my own PDR all assumed the save path was live. One curl showed 503 not-configured: zero accounts, zero rows, ever. It reordered the whole session and made the schema free to change. Probe production BEFORE reasoning about it, not after.

- P0 #the-blocker-i-carried-for-a-session-did-not-exist: The $5/mo Workers-Paid decision was described as load-bearing in the handoff, the boot snapshot and my own PDR: PBKDF2 ~29 ms against a 10 ms Free CPU limit means login FAILS. It registers in ~310 ms on the apex, four times in a row. A measurement carried forward as a fact is still only a measurement, and the cheapest way to retire it was to try it.

- P0 #applied-is-not-the-same-as-matches: apply-schema said "schema: OK" while the realm foreign key had silently not applied - CREATE TABLE IF NOT EXISTS is a no-op on an existing table, and the verifier only asked whether tables and indexes EXIST. Anything a schema file can add to a FRESH database but not an EXISTING one has to be asserted explicitly, or the gap is invisible exactly when it matters.

- P1 #the-plan-was-pre-taken-and-one-parameter-of-it-was-measurably-wrong: The handoff said DO NOT RE-PLAN these and it was right to. But A.0 is not re-planning: STEP_MS=190 means 5.26 local saves/second, so the pre-taken "5 s trailing debounce" could never fire while anyone was walking, and the pre-taken negative test ("a handful, not hundreds") would have passed with ZERO. Follow a pre-taken plan; still measure its numbers.

- P1 #the-test-found-the-bug-that-reading-had-walked-past-twice: I read push() closely enough to quote its header about stale, and still missed that it never calls isOutage() — so a 503 read as "the server refused your save". Harmless while nothing pushed; fatal with autosync, which treats rejected as final. The test caught it in seconds. Reading proves what code says; running proves what it does.

- P1 #i-rejected-a-bug-the-reviewer-invented: The applicability critic reported dropped[key]=item as an unguarded data-loss/grief primitive. Both write sites are guarded by an itemAt() check and the file even has a comment about the hazard. PRIME-AUDIT applies to the reviewer too — a confident critic is still a claim to verify.

- P1 #the-owner-reframed-and-it-changed-the-answer-not-just-the-scope: "Multiple servers, the world keeps living" turned autosync-the-blob from the fix into the wrong move: it would have made every player the author of a world meant to be shared. The code had called it years earlier — "this is the half a server takes over". Read what the codebase already knows before designing against it.

- P1 #a-credential-went-into-chat-because-i-asked-for-it-in-the-same-breath-as-the-file: I said "paste into the vault, not into chat" and he pasted into chat. Naming the file path and the exact line FIRST, before mentioning the value at all, would have made the file the obvious target. Rotated; the exposure is the instruction design, not the person.

- P4 #the-name-said-world-and-the-contents-said-player: worldFlags holds only era and intro.seen — both per-player progress. A future session moving it server-side because the NAME says world would give every player one shared intro.seen and one shared era. The most dangerous kind of misnaming is the kind that reads as a specification.

- P4 #a-grep-for-literal-calls-missed-the-dynamic-one: I reported worldFlags held exactly two keys, from grepping setFlag('name'). ParcelScene writes setFlag(act.openFlag) with a name from map data, so it also held a real world flag. The claim was confidently stated to the owner and was wrong. Grep finds the calls you can spell; it does not find the ones the data spells.

- P4 #the-failing-test-might-mean-the-data-is-gone: Six migration assertions failed with "keeps the era". The comfortable reading is "the test checks the old location". The other reading is "the era was lost". I migrated a real v8 blob in isolation and inspected it BEFORE editing a single expectation. Never update an assertion until you have proved which of the two it is.

- P5 #the-optimiser-satisfied-the-metric-and-produced-green-skin: An automatic pass to separate colliding night palettes turned a BLACK car bright orange and gave an NPC green skin with purple steel. Numerically valid, visually absurd. And the metric itself was wrong twice: comparing ONE step of a ramp fires on coincidence, and an absolute threshold punished materials that are near-identical in DAYLIGHT. A palette that satisfies a metric and looks ridiculous has not been fixed - the metric has been gamed.

- P5 #the-principled-fix-was-smaller-than-the-numeric-one: Dael and the crowd kept colliding with stone and gravel at night. The numeric answer was to shove their hues apart, which produced the green skin. The right answer was one line: they are PEOPLE, and people do not dim - the same rule that already exempted the player, and the one GSC shipped by leaving sprite palettes alone. When a constraint keeps fighting you, check whether the thing belongs in the constraint at all.

- P6 #it-looked-like-it-worked-and-half-the-palette-was-untouched: The LUT builder quantised with v>>2 and the shader with floor(v/255*63+0.5). 192>>2 is 48; the shader says 47. Forty-eight of 103 colours read an empty texel and passed through UNCHANGED - while the frame still lost a measured 23% of its luminance, so every summary number looked healthy. Found only by reading real pixels and noticing ONE colour was byte-identical at factor 0, 0.5 and 1 while its ramp neighbours moved. When two pieces of code must agree on a number, one of them has to be the definition; here it is the shader, because the shader is what does the lookup.

- P6 #i-measured-a-fade-and-nearly-reported-it-as-the-feature: My first pixel reading said night made the world BRIGHTER. The camera fade-in was still running at 42%, and my two grabs were two frames apart on a rising ramp - so I measured the fade, not the palette. Settling it first reversed the conclusion completely. A measurement taken during a transient is not a measurement of the thing.

- P6 #i-read-a-truthy-global-as-proof-and-it-was-a-pane-artifact: window.game existed, so I said the whole boot path ran. It was an empty object with no .scene and no .canvas in a 0x0 viewport, while the auth gate was still on screen - which would have meant the opposite. Giving the pane a real viewport settled it. Eight sessions of this repo learned not to read unmeasured frames; a truthy global is the same mistake wearing a different hat.

- P6 #the-author-said-the-player-holds-no-decisions-and-it-held-three: The audio module claimed its player function was dumb enough not to need testing, and it nearly was. Three decisions lived in the walk and in none of the data: skip-or-queue on a suspended context, claim-or-not on a turn that never sounded, and whether the gain ceiling survived. Each breakable without moving one number in the arrays. An adversarial pass found them and covered them with a witness that records and interprets nothing.

- HANDOFF #the-rule-was-written-and-broken-in-the-same-session: S120 wrote the rule "a needle must be a shape only CODE can have - never bind an assertion to a file a generator owns, because boot-snapshot.md is regenerated every handoff" and then bound THREE of its own assertions to boot-snapshot.md. They went red on the very next handoff, at the close gate, after everything else was already green. Writing a rule is not the same as obeying it, and the gap is invisible until the generator runs. Rebound to the claim: the harness exists (tools/shoot.ts) and 114 frames are on disk - neither of which a generator rewrites.
