## THE ARCHITECTURE, AND WHY IT IS SHAPED THIS WAY

### 1. MULTIPLAYER DECIDED THE DATA MODEL — do not undo this

Daniel: *"as an open world craft/sandbox multiplayer rpg SHOULD BE."*

A bottle on a shelf is **not my bottle** — two players must see the same shelf. So `SaveStore` v3
splits:

| State | Owner | Contents |
|---|---|---|
| `carried` | the PLAYER | what you're holding |
| `world` | the WORLD | `taken` (container deltas) + `dropped` (positions) |

**Folding these together would work perfectly today and make multiplayer a rewrite.** The archived
build already ships `gateway.ts`, 34 handlers and `action-sanitizer.ts` — which is also why every
item method is a **command**, not a scene mutation. The client requests; an authority decides.

### 2. Items are ENTITIES, never legend glyphs

Same rule as NPCs and vehicles. Verified: `palette-check` reads `map.legend[ch].tile` and nothing
else, so an entity's palette costs the scene zero. `bottle_empty` uses the existing FOLIAGE ramp
rather than a new palette — the ramp already *is* bottle-green, and a fifteenth unanchored palette
would widen the colour-anchoring gap `evidence-check` already reports.

### 3. A container is an interactable whose options are its contents

This is what let the whole priority ship with **no new UI**. `container: {id, holds}` on an
interactable; `holds` is the ORIGINAL and is never rewritten; the save records only the delta. A
container's options are computed at the moment of looking, which is why `prompt` couldn't stay
static.

`hitTile` is now **optional** — a stone shelf has no struck frame because searching a shelf does not
deform it. §9.2 is still satisfied: the player lunges, a sound plays.

### 4. Dropped items BLOCK

A bottle you can stand on is a decal, not an object. It also kills Stardew's
drop-then-instantly-hoover-it-back-up trap outright, with no timer.

**Consequence you must not forget:** an item makes its tile unwalkable, and `create()` throws on a
warp that is not walkable. A bottle left in a doorway would be a **crash on next load**, so
`canPlaceAt` refuses doorways and items spawn AFTER warp validation. Both belts.

### 5. A TAKE CAN NEVER BE REFUSED

The Council's answer to the soft-lock: fill your hands and you can no longer pick up what the game
requires. Facing a dropped item with full hands **swaps** — the tile you face is exactly where your
own item would go, so it needs no prompt and you can never end up holding nothing.

A **container** declines instead, drawn dim in the S109 idiom, because putting a thing *onto* a
shelf is a different verb that does not exist yet.

## THE INPUT MODEL — DECIDED, NOT YET BUILT

Daniel killed my one-button design with a better argument: *"its weird that push/pull actions or
do/undo give/take actions all have the same key."* ARK splits four ways and holds for extended
actions. **Inverse operations do not share a key.**

| Key | Tier | Verbs |
|---|---|---|
| `F` / `Enter` | **ENGAGE** — reach *into* the world | Take · Knock · Unlock · Talk · Fill · Look |
| `1` / `2` | **HANDS** — act *with* what you hold | Place · Spill · Strike · Throw · Ingest |
| `I` | **SUBSCREEN** | 3×3 grid + two hand slots |

- **HIT vs THROW:** same key. **Tap** = strike what's in front of you. **Hold** = a reticle appears
  and **arrow keys choose the target tile** (Daniel's upgrade), release to throw. Reticle back on
  your own tile = cancel.
- **Throw physics:** Manhattan range ≤ 4, stops at the first blocking tile or entity, breakables
  shatter and spill, and it **never resolves onto an unreachable tile**.
- **Predictability rule:** `F` acts instantly when the only verb is safe and reversible; it **always
  asks before anything irreversible**. (This resolved a direct Grok/Gemini contradiction — the axis
  is reversibility, not option count.)
- **Presentation:** the **Verb Cross** — four 16×16 icons around the target, pick with the d-pad.
  Caps at 4; 5+ falls back to the message box. Past ~8 is a **known ceiling, not solved.**
- **DO NOT BIND `Ctrl` OR `Alt`** — browser game. `Ctrl+W` closes the tab, `Alt` grabs the menu bar.
  `SPACE` (reserved for jump/climb) needs `preventDefault()` or the page scrolls.
- Every action needs **two** bindings: the game supports WASD *and* arrows.

### The Crystal test, for every future mechanic

> **Can it be said in tiles, facing, one button, and a box?**

Crystal is the **grammar, not the ceiling**. Refuse: analog movement, mouse aiming, a HUD of bars,
real-time hitbox combat, camera zoom.

### Headless testing — you will need this

**When the Browser pane is not compositing, `requestAnimationFrame` never fires.** `create()` runs
but `update()`, the Clock and tweens do not — and **`game.loop.actualFps` reports a default 60 while
`game.loop.frame` sits at 0.** Check the frame counter, never the fps.

```js
let T = 1000;
const step = (ms) => { const dt = 16.666; for (let e = 0; e < ms; e += dt) { T += dt; game.step(T, dt); } };
```

`scene.time.update()` alone is not enough (events merge in `preUpdate`), and `scene.tweens.update()`
does not advance tweens at all in Phaser 3.90.
